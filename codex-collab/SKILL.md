# Claude 与 Codex 分工

本模式从调用起持续到对话结束，或用户说明退出。调用时附带的任务：$ARGUMENTS（为空时指当前对话中的任务）。

Claude 负责需求澄清、方案取舍、界面与交互设计、任务交接、审核和收尾；
Codex 承担可独立交接的执行工作，无需用户逐项点名。

- Claude 直接做：回答问题、确认业务口径、支撑决策和审核的定点阅读、影响局部且无需连续调查的直接修改，以及给人直接阅读或执行的
  最终产物（操作手册、命令清单、分析报告）；需要 Codex 先调查或批量整理的，Claude 基于其结果改定后交付。
- Codex 执行：方向明确后的代码实现、缺陷修复、批量文档修订、SOP 与验收用例的批量整理、核对和合并。业务口径由用户确认，界面与交互由 Claude 定好后交接。
- Codex 调查：大范围资料整理、跨文件或跨仓追踪、根因诊断，以及需要不同源模型提供第二意见的判断。
- Explore 子代理：快速只读定位。需要成批核对、持续追踪或形成完整报告时交给 Codex。
- 用户：真实账号登录和业务决策。

按工作内容分配，不以“预计超过 10 分钟”为门槛。局部工作扩大为连续调查或批量处理时，重新分配；需要当前对话背景时，把相关要求和已确认取舍写进交接。
上述 Codex 工作使用 Codex，不用普通 Claude 子代理替代。Codex 无法执行时先说明具体原因和接续方式；能在已有授权内解决的启动或环境问题直接处理。

1. 方案：先确定目标、范围、关键约束和完成依据。需要大范围调查才能确定方案时，先交给 Codex 调查；涉及尚未确认的业务取舍时请用户决定。
2. 交接：写明目标、输入材料、允许修改的范围、已确认取舍、预期产物和完成依据。
   代码改动写明对应的 SOP 场景及真实入口验证方法；调查和文档任务写明依据、覆盖范围及结果格式。
   补充仓库文档没有写明的信任边界和范围外事项。核实前提、越界时停止、报告取舍沿用 Codex 的全局约定。
   开发中不产出单元测试、接口测试和集成测试；业务交付以 SOP 场景经真实入口执行的结果验收。
   启动前核对执行环境实际允许写入的目录是否覆盖任务范围，跨仓任务逐仓核对；任务说明里的授权不能代替环境权限。
   要求改动留在工作区未提交；提交、推送、reset、stash、删除目录或大批文件和凭据操作留给 Claude，并遵守用户授权及当前权限。
3. 启动：直接调用 `node ~/.claude/plugins/cache/openai-codex/codex/<版本>/scripts/codex-companion.mjs task --background [--write] "<任务>"`（需要写文件的任务加 --write，包括文档和用例整理；纯只读调查不加），
   再用后台 Bash 循环执行 `status <job-id> --json`，直到状态离开 `queued`/`running`，这样完成时会收到通知；
   循环到达 2 小时上限时续起。关闭 Claude 会话会终止插件任务，超过 2 小时的工作拆成各有验收点的小段；
   是否使用 git worktree 由用户指定。
   需要联网的调查不走插件（插件的只读沙箱禁网）：任务说明写入文件，在仓库目录用后台 Bash 运行
   `codex exec --json -o <结果文件> - < <任务文件> > <事件日志>`（任务放在参数里时后台 stdin 不结束，Codex 会一直等输入），
   按 config 的 `danger-full-access` 执行，不加 `--ephemeral`；任务说明写明不得修改文件，交回后检查 `git status`。
   命令行抓取被 Cloudflare 拦截的网页，让 Codex 用 chrome 插件在用户的 Chrome 中只读浏览，任务说明写明不登录、不发言、不点赞。
   会话 id 取事件日志中 `thread.started` 的 `thread_id` 并记入任务记录；返工在同一目录运行
   `codex exec resume <id> --json -o <结果文件> - < <说明文件>`，不用 `--last`。
4. 重叠：Claude 编辑时提示文件在上次读取后已被改动，或补丁上下文对不上，就说明还有任务在改同一处。
   此时重新读取，在当前内容上合并，保留对方的改动，然后重跑双方相关的测试。交给 Codex 的任务说明里同样写明：
   发现文件与自己读到的内容不一致时，基于最新内容合并，并在报告中列出这些文件。
5. 审核：Codex 交回后，由 Claude 核对产物并给出结论；此授权覆盖插件命令“只原样返回输出”的要求。
   先读结果正文，区分已完成、部分完成和受阻；插件显示 completed 只表示运行结束。
   调查和文档任务核对来源、覆盖范围及实际产物；代码改动逐项对照需求和 diff，并按既有标准安排真实入口的独立验收。
   实现会话的自检不计入独立验收。代码再次改动后，重新验证受影响的场景。以最初的需求和项目原则为准绳，不以 Codex 的解释为准，对照实际产物排查以下常见偏差:
   - 越界：换框架或依赖、改上游项目或去开 issue/PR、改坏范围外的功能。
   - 答非所问：解决了自己设想的问题，无视写明的原则和条件。
   - 过度设计：为不存在的攻击者或不会发生的场景加防御层，多余的抽象和转发。
   - 坏取舍：为次要目标牺牲功能（如搜索太慢就不搜、假装无结果）。
   - 冒充完成：用测试或模拟环境自证，只接通基础功能，发现问题停下不修。
   Codex 的审查意见和第二意见（含对 Claude 方案的批评）是待验证的假设：严重程度重新评估；每条查到能判定它是真实缺陷、
   刻意取舍、可选改进、范围外还是误报为止，同根因的合并；只修确认存在的，修法自己选，改后复查调用方和邻近逻辑。
   不合格时写返工说明，按该任务记录的 Codex 会话编号续接，使用第 3 步的 codex exec resume <id> 命令，并核对续接后的权限仍符合任务范围。
6. 收尾：向用户报告结论和未完成项；提交、推送、合并在用户确认后由 Claude 执行。审核中遇到清单之外的新偏差，
   报告时提议补进本技能第 5 步（源文件为 praxis-skills 仓库的 `codex-collab/SKILL.md`）。

# 用例转换与语义去重

测试同事提供用例时先读本页。用例是验收标准，SOP 场景补充用例尚未覆盖的业务保证。用例文件与配对文件的结构见[文件格式](formats.md#测试同事的用例文件)。有看板时按[看板模式](board.md#上传与取回)上传并取回合并结果；以下转换用于没有看板的仓库，对齐总体方案 S7 与 SOP-BOARD-3 I4。

## 逐条转换

对历次用例的并集按编号取最新内容，每条用例生成一条同编号场景：

| 场景内容 | 取值 |
| --- | --- |
| `id`、`title`、`priority`、`tags` | 用例同名字段 |
| `refs` | 含用例编号的数组 |
| `polarity` | 用例 `tags` 含 `negative` 时为 `negative`，其余为 `positive` |
| `initial_state`、`steps`、`expected` | 分别取 `preconditions`、`steps`、`expected_results`，保留解析后的原文 |
| `forbidden_effects` | 初始为空数组；去重时并入原 SOP 场景独有的禁止副作用 |
| `actor`、`verify` | 依据用例填写角色，选择已声明的入口名 |
| `negative_type` | 反向场景按[枚举](formats.md#场景文件)选择，其他类型取 `other` |
| `regression` | 重新合并时按场景编号保留；首次由[沉淀流程](distill.md)写入 |

用例缺 `preconditions` 时补写初始状态，并在对应关系中注明依据和 `# 待确认`；其他必需信息缺失或结果不足以判定时，按[确认步骤](../SKILL.md)取得具体内容后继续。

## 节点与来源

按用例 `tags` 中的 `section:` 值分组，缺少该标签的归入“未分组”，节点 `title` 取分组名。首次将用例按编号排序，按分组首次出现的先后分配 `S01`、`S02`……；“未分组”和并入其他节点的分组同样占号。将分组与编号的对应保存在场景文件注释中，同批次再次转换时沿用，新分组取下一个编号。

节点的 `actor`、`entry` 依据用例与入口填写。只有反向用例的分组可并入有相同业务上下文的节点，保留其原分组编号；仍缺正向依据时列出缺口，取得确认后补齐。只有正向的节点按[节点规则](formats.md#场景文件)补反向场景或写明豁免；推断的豁免理由先标待确认。

`metadata.requirement` 取批次需求名，只有用例的新批次取 `metadata.feature`；`batch` 取批次名，`version` 取用例并集版本，`owner` 取用例文件的 `metadata.owner`。来源指向用例批次与版本，`confirmed_by` 取该 owner，同时保留补充场景的 SOP 来源。本机版本用导入快照序号标识，在来源中记录用例文件位置，按[状态目录](formats.md#本机记录与报告)中的 `cases/imports/` 快照核对序号。

## 补充场景的去向

逐条比较原 SOP 场景与用例场景的角色、初始状态、入口、预期及禁止副作用，按业务含义判断。每条原场景在仓库外的对应关系记录中写一种去向：

- **保留**：用例尚未覆盖的保证，保持原编号与内容，放在原节点；原节点失去正向场景时移入适合的用例节点并记录移动理由。
- **重复**：角色、初始状态、入口与全部结果保证均被目标用例覆盖。写原场景编号、目标用例编号及逐项理由，把独有的 `forbidden_effects` 并入目标；目标没有回归声明时转移原声明。
- **冲突**：同一上下文的预期相反。写目标用例及理由，向负责人澄清，以已确认的用例为准处理，保留处置记录。

补充场景使用区别于用例的编号，已有非用例场景占用 `TC_` 编号时先明确编号迁移关系。编写[配对文件](formats.md#配对文件)，使每条用例恰好归入一类。运行 `check`、`import-cases`、`coverage`，处理所有遗漏、重复归类与冲突，覆盖核对通过后交接执行。
